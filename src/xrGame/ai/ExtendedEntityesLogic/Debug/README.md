# Debug — общая отладка ExtendedEntityesLogic

Статус: план подсистемы. Исходники ещё не реализованы. Эта инструкция определяет их ответственность и способ подключения.

## Файлы

| Файлы | Класс | Назначение |
| --- | --- | --- |
| `Debug.h/.cpp` | `CELSharedDebug` | Публикация данных, очереди, объединение записей, тайминги, фильтры и подготовка снимков |
| `DebugCommands.h/.cpp` | `CELSharedDebugCommands` | Консольные команды и их регистрация; управление состоянием Debug |
| `DebugDrawHud.h/.cpp` | `CELSharedDebugDrawHud` | Текст и счётчики на HUD |
| `DebugDrawWorld.h/.cpp` | `CELSharedDebugDrawWorld` | Примитивы и подписи в 3D-мире |

Пара `.h/.cpp` соответствует одной ответственности. Общие небольшие типы сообщений находятся рядом с Debug, без отдельного файла на каждый вид примитива.

## Включение и потоки

Отладка по умолчанию выключена и временно включается консольными командами из DebugCommands. Она не является частью отдельного вычислительного потока пространственных и графовых задач. Обслуживание отладки и рисование выполняются штатными стадиями движка через EntryPoint. Безопасная публикация сообщений из вычислительной задачи, если понадобится, не переносит туда тайминги, команды или отрисовку Debug.

## Поток данных

```text
Логика, память, навигация, движение, бюджеты
    └── Публикация значений и событий
        └── Debug
            ├── Очереди, ключи записей, фильтры и расписание
            ├── Снимок HUD → DebugDrawHud
            └── Снимок мира → DebugDrawWorld

Консоль → DebugCommands → настройки Debug
```

Все группы и конкретные виды используют одну подсистему отладки на игровой мир. Собственные отладочные менеджеры в сущностях не создаются. Существующие средства вывода движка используются из отрисовщиков, а не копируются.

## Публикация из игровых слоёв

- Игровой код передаёт значения, идентификатор сущности/владельца, канал и ключ записи через API Debug. Он не вызывает рисование и не хранит таймеры отладки.
- Текущее состояние обновляется по ключу `(мир, владелец, канал, запись)`. Новая публикация заменяет прежнее значение вместо накопления копий каждого кадра.
- Одноразовые события, например начало атаки или отказ проверки маршрута, публикуются как события с ограниченным сроком жизни.
- В сообщениях нет указателей на временные данные, CBlend, текущие контейнеры путей или уничтожаемые сущности. Геометрия и строки копируются в ограниченные собственные буферы либо в безопасный снимок.
- Записи разных групп не смешивают владельцев: идентификаторы учитывают повторное использование игровых ID и поколение мира.

Точные сигнатуры API задаются при реализации. Не добавлять отдельные таймеры в монстров ради выполнения этого контракта.

## Очереди и тайминги

Debug владеет временем жизни записей, частотой подготовки снимков и подавлением повторов. Отрисовщики только отображают подготовленные данные.

Дешёвые значения можно публиковать при изменении. Для дорогого сбора Debug определяет, нужен ли снимок для данного владельца и канала сейчас; игровой слой выполняет сбор только по этому допуску. Собственный периодический таймер в сущности не заводится. Не сохранять в планировщике небезопасные обратные вызовы с сырыми указателями на игровые объекты.

Очереди имеют фиксируемые пределы по записям и объёму данных. Переполнение объединяет либо отбрасывает отладочные данные по определённому правилу и увеличивает диагностический счётчик. Оно не блокирует игровую симуляцию.

Публикация из рабочих стадий и чтение в рендере согласуются через ограниченную очередь и смену подготовленных буферов в определённой точке кадра. Рисование и дорогое форматирование не выполняются под блокировкой очереди.

При отключении канала дорогой сбор не запускается. При удалении владельца его записи удаляются централизованно; завершение мира очищает очереди и расписание. Отладочное состояние не сохраняется в игровых сохранениях.

## HUD и мир

`DebugDrawHud` выводит строки состояния выбранных сущностей, сводные счётчики и причины ожидания. Разметка, форматирование и ограничения количества строк находятся здесь.

`DebugDrawWorld` рисует маршруты, линии связей, точки, сферы и подписи в мировых координатах. Вся мировая отрисовка выполняется исключительно через `HUD().world_prims` внутри `DebugDrawWorld`. Отдельный рендерер мировых примитивов не создаётся; прямые вызовы `HUD().world_prims` из классов сущностей и глубинных слоёв логики не добавляются. Например, факт окна атаки публикуется игровым кодом, а красный цвет сферы и срок его отображения определяются отладочной подсистемой.

Выдача данных регулируется расписанием Debug, но фактическое рисование выполняется только в разрешённой движком стадии HUD/мира. Отрисовщики не запускают AI, построение пути или выбор целей и не держат собственных конкурирующих таймеров.

## Консоль и подключения

Реализация новых отладочных команд и их регистрация находятся в `DebugCommands`. Команды изменяют включение каналов, фильтры владельцев/групп, частоты обновления, сроки жизни и ограничения отображения через Debug. Конкретные имена команд фиксируются при реализации.

Во внешнем коде движка остаются минимальные вызовы корневого `EntryPoint.h/.cpp`: регистрация команд, обслуживание кадра, отрисовка в правильных стадиях и завершение мира. EntryPoint делегирует регистрацию в DebugCommands, обслуживание очередей в Debug и отображение в соответствующие отрисовщики. Отдельные реализации Debug снаружи модуля напрямую не подключаются. Не распределять обработчики команд и форматирование отладки по классам монстров.

## Как расширять

1. Определить, является информация текущим состоянием или одноразовым событием.
2. Добавить канал/полезные данные к общему API, если существующих типов недостаточно.
3. Публиковать данные там, где факт уже известен; не пересчитывать игровую логику ради отображения.
4. Добавить представление в HUD или мире и при необходимости управление каналом в DebugCommands.
5. Обновить эту инструкцию при изменении контракта, владения или порядка подключения.

Общий экземпляр Debug доступен через внутренний механизм модуля; EntryPoint согласует его жизненный цикл с уровнем. Инициализация одиночки сама по себе не заменяет очистку очередей при завершении мира. EntryPoint не обновляет сущности: они публикуют данные при собственных обновлениях CBaseMonster.
